# WORKFLOW — چرخه کار

## گام‌ها

| گام | خروجی عبور |
|-----|-------------|
| انتخاب کار | شناسه `WP-*`، منبع FR/GAP، دامنه |
| آمادگی | DoR کامل — [`DEFINITION-OF-READY-AND-DONE.md`](DEFINITION-OF-READY-AND-DONE.md) |
| طراحی | قرارداد/ریسک/طرح تست/مستند |
| پیاده‌سازی | محدوده مصوب؛ بدون secret در کد |
| آزمون | نتیجه واقعی + گزارش — [`TESTING-STANDARD.md`](TESTING-STANDARD.md) |
| بازبینی | معماری، امنیت، تست، DOC |
| تحویل | CHANGELOG/Unreleased، providers، ROADMAP |
| پذیرش | نقش مجاز؛ DoD؛ جدا از tag |

## نقش‌ها (بدون نام فرد)

| نقش | مسئولیت |
|------|----------|
| مالک محصول | دامنه، DEC، Production Verified |
| maintainer فنی | معماری، پذیرش merge، استاندارد |
| توسعه‌دهنده | پیاده‌سازی در محدوده WP |
| مسئول آزمون | شواهد TEST-MATRIX |
| بازبین امنیت | موارد حساس شعب/اسرار |
| نگهدارنده DOC | فارسی و providers |
| مسئول انتشار | RELEASE-CHECKLIST، tag (آینده) |

یک نفر می‌تواند چند نقش داشته باشد؛ **تأیید و اجرا** باید جدا ثبت شود.

## وضعیت کار

`پیشنهادی` → `مصوب` → `آماده` → `در حال انجام` → `بازبینی` → `پذیرفته` | `مسدود` | `تعویق` | `خارج از دامنه`

تغییر وضعیت در ROADMAP/WP فقط با شاهد.

## سیاست Git (پیشنهادی — مصوب نشده)

- شاخه feature از `main`
- MR با لینک `WP-*` و چک‌لیست DoD
- بازبین حداقل یک نفر غیرنویسنده برای تغییر قرارداد عمومی

اگر مخزن سیاست دیگری دارد، مالک در CONTRIBUTING به‌روز کند.

## بازبینی اجباری اضافی

- migration و config پیش‌فرض
- قرارداد عمومی / breaking
- احراز هویت و جداسازی شعب
- همگام‌سازی کاتالوگ (`catalog_sync`)
- تغییر رفتار درایور — `docs/providers/`
