# سیاست نسخه‌بندی و انتشار (پیشنهادی)

**وضعیت:** پیش‌نویس مرحله ۴.۶ — **نیازمند تصویب مالک محصول** قبل از اعلام رسمی.

## اصل پیشنهادی: SemVer

شماره `MAJOR.MINOR.PATCH` (نسخه‌بندی معنایی):

| افزایش | زمانی (پس از تصویب) |
|--------|----------------------|
| MAJOR | تغییر ناسازگار قرارداد عمومی، schema اجباری نامتناسب، حذف API پشتیبانی‌شده |
| MINOR | قابلیت سازگار با عقب، migration اختیاری، config جدید با پیش‌فرض امن |
| PATCH | اصلاح باگ سازگار، مستندات، تست |

**تفکیک مستقل:** نسخه پکیج (`13.x`)، نسخه Laravel (`^13`)، نسخه API سرویس‌های خارجی و شماره فاز مستندسازی — مگر سیاست مصوب خلاف آن را تعریف کند.

## وضعیت‌های انتشار

| وضعیت | تعریف |
|--------|--------|
| نسخه فنی در مخزن | `composer.json` + tag محلی/remote |
| نسخه منتشرشده | در دسترس `composer require` از منبع اعلام‌شده |
| نسخه پایدار | بدون تغییر شکسته‌کننده برنامه‌ریزی‌شده در همان MINOR |
| Production Verified | تأیید مالک پس از تست میزبان، DB هدف و کانال‌های مورد نیاز |

**هیچ نسخه‌ای صرفاً به دلیل سبز بودن PHPUnit SQLite به عنوان Production Verified معرفی نمی‌شود.**

## alpha / beta / RC

فقط به‌عنوان سیاست پیشنهادی؛ شماره آینده در ۴.۶ قطعی نشده است.

## منسوخ‌سازی

- اعلام در `CHANGELOG` با جایگزین و مهلت — مهلت **بدون تصمیم مالک تعیین نمی‌شود**
- حذف درایور یا فرمان: MINOR منسوخ، MAJOR حذف

## ثبت تغییر

- هر کار تکمیل‌شده در بخش `Unreleased` در [CHANGELOG.md](../../CHANGELOG.md)
- الگو: [CHANGE-ENTRY-TEMPLATE.md](CHANGE-ENTRY-TEMPLATE.md)
- انتشار: [RELEASE-CHECKLIST.md](RELEASE-CHECKLIST.md)

## کنترل CI (پیشنهاد متنی — بدون پیاده‌سازی در ۴.۶)

- هنگام bump نسخه: وجود بخش نسخه در CHANGELOG و در صورت نیاز به‌روزرسانی UPGRADING
- تطابق `composer.json` version با tag
- عدم commit بدون ورودی Unreleased برای تغییرات رفتاری

## سرویس‌دهندگان خارجی

تغییر API کانال‌ها در تاریخچه پکیج نیست؛ ارجاع به [docs/providers/](../providers/) و فاز ۴.۲.
