# ماشین وضعیت انتشار

این سند چرخهٔ وضعیت رکورد انتشار و مالکیت تغییرات خارجی را برای STEP 05 و STEP 06 ثبت می‌کند. تغییر status فقط از مسیر `Publication::transitionTo()` انجام می‌شود؛ claim انتشار و mutation خارجی عملیات شرطی جداگانه‌ای هستند.

## وضعیت‌ها و انتقال‌ها

| وضعیت فعلی | وضعیت مجاز بعدی | توضیح |
| --- | --- | --- |
| `Draft` | `Scheduled`, `Publishing`, `Failed`, `Cancelled` | شکست اعتبارسنجی پیش از ارسال به `Failed` می‌رود و شمارندهٔ ارسال را تغییر نمی‌دهد. |
| `Scheduled` | `Publishing`, `Draft`, `Failed`, `Cancelled` | رکورد نامعتبر پس از سررسید از query زمان‌بند خارج می‌شود. |
| `Publishing` | `Published`, `Failed`, `UnknownOutcome` | نتیجه فقط با مالکیت همان `attempt_token` ثبت می‌شود. |
| `Failed` | `Publishing`, `Scheduled`, `Cancelled` | retry دوباره claim شرطی می‌گیرد. |
| `UnknownOutcome` | `Failed` | فقط مسیر retry دستیِ تأییدشده اجازهٔ بازگشت به صف را می‌دهد. |
| `Published` | `Deleted` | پس از موفقیت حذف خارجی، شناسهٔ فعال پاک و شناسهٔ تاریخی در metadata باقی می‌ماند. |
| `Cancelled`, `Deleted` | — | وضعیت پایانی؛ Job انتشار آن‌ها را نادیده می‌گیرد. |

## مالکیت و هم‌زمانی

- claim یک UPDATE شرطی از Draft/Scheduled/Failed به Publishing است؛ افزایش `attempts` در خود SQL انجام می‌شود.
- هر claim یک `attempt_token` UUID در پایگاه داده ثبت می‌کند. این فیلد از JSON مدل پنهان است و با پایان تلاش پاک می‌شود.
- انتقال وضعیت مقدار status قبلی را شرط می‌کند. انتقال از Publishing علاوه بر status باید با token مالک جاری تطبیق داشته باشد.
- لغو و زمان‌بندی نیز همین انتقال شرطی را به کار می‌برند؛ نمونهٔ قدیمی نمی‌تواند وضعیت تازه را بازنویسی کند.
- درخواست شبکه بیرون تراکنش است. تکمیل log و ثبت نتیجهٔ انتشار در یک تراکنش کوتاه انجام می‌شود؛ رویدادها پس از commit dispatch می‌شوند.
- رکوردهای متوقف با `Publication::stuckInFlight($before)` قابل یافتن‌اند؛ این query مقدار timestamp خالی را نیز برای رکوردهای قدیمی برمی‌گرداند. گذشت زمان آن‌ها را خودکار قابل retry نمی‌کند؛ نتیجه باید بررسی شود.

## ویرایش محتوای منتشرشده

- Update و Delete از یک `attempt_token` مشترک روی رکورد Published استفاده می‌کنند؛ عملیات هم‌زمان نمی‌تواند نتیجهٔ کهنه را روی رکورد بنویسد.
- Update یک clone پیشنهادی را اعتبارسنجی می‌کند. تغییر فیلدهای اعلام‌نشده در `ChannelCapabilities` یا پاک‌کردن فیلد غیرقابل‌پاک‌سازی پیش از درخواست خارجی رد می‌شود.
- `content_version` نسخهٔ محتوای تأییدشده است و claim آن را شرط می‌کند. فقط پس از پاسخ موفق، محتوا، نسخه و `last_synced_at` با هم ذخیره می‌شوند.
- شکست قطعی یا نامشخص محتوای تأییدشده را تغییر نمی‌دهد؛ پیشنهاد و `sync_status` در `metadata.omnichannel.content_sync` نگه‌داری می‌شوند. نامشخص به معنی موفقیت نیست.
- موفقیت API و شکست پایگاه داده قابل بازسازی کامل خودکار نیست؛ تطبیق با API خارجی در این مرحله پیاده نشده است.

## حذف، غیرفعال‌سازی و تاریخچه

- حذف خارجی فقط پس از پاسخ موفق وضعیت را Deleted می‌کند؛ شناسه(ها) و زمان حذف در metadata باقی می‌مانند و رکورد انتشار و log از مسیر سرویس حذف نمی‌شوند.
- غیرفعال‌سازی قرارداد اختیاری `DeactivatableChannelDriver` دارد. موفقیت آن در `omnichannel.deactivation` ثبت می‌شود؛ status Published و شناسهٔ خارجی حفظ می‌شوند چون فهرست حذف نشده است.
- Delete و Deactivate هر دو قفل mutation و log جدا دارند. نتیجهٔ نامشخص قفل را نگه می‌دارد تا نتیجهٔ خارجی بررسی شود.
- Bot API تمام `message_id`های آلبوم را پایدار می‌کند. حذف ترتیبی است؛ پس از هر عضو موفق، باقی‌مانده ثبت می‌شود و خطای میانی موفقیت کامل محسوب نمی‌شود.
- رکورد قدیمی تک‌شناسه‌ای فقط همان شناسه را حذف می‌کند؛ اعضای دیگر قابل کشف یا حدس نیستند.
- migration جدید حذف channel/connection دارای publication را محدود می‌کند و با حذف publication، logها را با `publication_id = null` نگه می‌دارد. Upgrade روی MySQL/PostgreSQL تغییر می‌کند؛ SQLite فقط در نصب تازه قیدهای جدید را از migration پایه می‌گیرد.

## نتیجهٔ شکست پیش از ارسال

اعتبارسنجی یا اتصال نامعتبر قبل از claim، status را به Failed می‌برد و `failed_at`، `failure_class`، `error_code` و پیام پاک‌سازی‌شده را ثبت می‌کند. در این مسیر `attempts` و `last_attempted_at` دست‌نخورده می‌مانند.

## محدودیت آزمون

تست‌ها رفتار شرطی را با SQLite درون‌حافظه‌ای تأیید می‌کنند. رقابت واقعی چندپردازه و سازگاری نحوی قفل‌ها/عبارت‌های اتمیک با پایگاه دادهٔ میزبان باید در STEP 09 روی driver تولیدی آزموده شوند.
