# راهنمای ارتقای Omnichannel

## STEP 05 — مالکیت تلاش انتشار

این نسخه migrationهای افزایشی برای `attempt_token` nullable و `content_version` با مقدار پیش‌فرض صفر در جدول publications اضافه می‌کند. نام جدول از تنظیمات پکیج خوانده می‌شود؛ foreign key جدیدی به میزبان افزوده نمی‌شود.

پیش از ارتقا:

1. از پایگاه داده نسخهٔ پشتیبان بگیرید.
2. workerهای صف Omnichannel را متوقف یا تخلیه کنید تا کد قدیمی هم‌زمان با migration وضعیت انتشار را ننویسد.
3. migrationهای پکیج را اجرا و سپس workerها را با نسخهٔ جدید راه‌اندازی کنید.

ستون تازه nullable است؛ رکوردهای قدیمی و تلاش‌های قبلی نیاز به backfill ندارند. پس از migration، claimهای تازه token خواهند داشت. مقدار token داخلی است و از JSON مدل پنهان می‌ماند.

`content_version` برای رکوردهای پیشین صفر می‌ماند و backfill لازم ندارد. Update فقط فیلدهایی را می‌پذیرد که قابلیت درایور اعلام کرده است. نتیجهٔ نامشخص محتوای قبلی را نگه می‌دارد و proposal را در `metadata.omnichannel.content_sync.pending_content` ثبت می‌کند.

## STEP 07 — نگهداری انتشار و log

قیدهای foreign key برای جلوگیری از حذف channel/connection دارای publication محدود می‌شوند. log با حذف publication حفظ و `publication_id` آن null می‌شود. اتصال دارای سابقه را غیرفعال کنید؛ حذف آن دیگر مجاز نیست.

در MySQL و PostgreSQL، migration افزایشی قیدها را تبدیل می‌کند. SQLite نمی‌تواند این قیدهای نام‌دار را با مسیر فعلی درجا تغییر دهد؛ نصب تازه از schema اصلاح‌شده استفاده می‌کند، اما ارتقای SQLite تا بررسی مرحلهٔ ۰۹ باید جداگانه مدیریت شود. پیش از ارتقا از پایگاه داده نسخهٔ پشتیبان بگیرید.

اعتبارسنجی ناموفقِ انتشار Draft یا Scheduled اکنون رکورد را Failed می‌کند؛ این رکورد دیگر در انتخاب زمان‌بند قرار نمی‌گیرد. درخواست retry از نتیجهٔ `UnknownOutcome` همچنان به تأیید دستی نیاز دارد.

تغییرات WhatsApp Catalog در `items_batch` می‌تواند پذیرفته شود بی‌آنکه پایان عملیات تأیید شده باشد. از این نسخه 2xx/handle به Published/Deleted تبدیل نمی‌شود؛ نتیجه در حالت UnknownOutcome می‌ماند و عملیات دیگر برای همان انتشار تا بررسی batch مسدود است. رکوردهای مبهم قبلی که پیش‌تر موفق ثبت شده‌اند به‌طور خودکار شناسایی یا اصلاح نمی‌شوند. راهنمای رفتار و منابع رسمی در `CHANNEL-CAPABILITIES.md` است.

برای مشاهدهٔ دستی وضعیت و خطاهای ذخیره‌شدهٔ Meta از `php artisan omnichannel:inspect-whatsapp-batch {publication_id}` استفاده کنید. این فرمان mutation تازه نمی‌فرستد و وضعیت محلی را نهایی نمی‌کند؛ تا زمان اضافه‌شدن poller و بررسی امن خطاهای هر item، اپراتور باید نتیجه را بازبینی کند.
